# Codebase Audit — 2026-09-26

Full-codebase audit covering AI/LLM, subscriptions/monetization, data/sync/background-tasks, UI/theming, and security/testing/stability. Findings below are verified against the actual code at HEAD (`16dabf0`, v3.0.4 build 10) — two initial automated passes produced false positives (noted where relevant) and were corrected by direct inspection before inclusion here.

## 🔴 Release-blocking (confirm before shipping)

**Monetization is fully disabled.** `Core/Services/SubscriptionService.swift:16` — `allFeaturesFree = true`; `updateTier` hardcodes every user to `.deep`. Confirmed **intentional**: commit `4361d43` ("Bypass subscription gating: SubscriptionService.allFeaturesFree unlocks every tier"), landed 2026-07-02, still live at HEAD. Not a bug, but the entire paywall/gating code path (CLAUDE.md's tier table, `PaywallView`, Ask-lock in `AskView.swift:70/161`) is currently dead weight while this flag is on. Confirm this is still the plan before 3.0.4 ships.

## 🟠 Bugs (file:line, verified against real code)

1. **`Core/Persistence/MirrorModelContainer.swift:18`** — `fatalError` on `ModelContainer` init failure, no recovery path. A corrupted store or disk-full condition on launch causes a permanent crash loop; only fix is reinstall, which loses local data.
2. **`Core/Services/InsightService.swift:1791-1805`** (`buildAskMessage`) — the user's question is appended *last* in the composed prompt, then the whole string is clipped to a 5,700-char budget as one unit. A long question combined with a full entries/background budget can silently truncate or drop the question entirely, with no error surfaced. `AskView`'s question field has no length cap.
3. **Ask cap (15/month, Core tier) is enforced client-side only**, derived from a local SwiftData query (`AskView.swift:55-60`) with no server-side backing. Two CloudKit-synced devices can each observe `remaining > 0` before the other's writes propagate, allowing roughly 2x the intended cap. It is also resettable by moving the device clock forward and back a month (`DateHelpers.swift:23-26`, uses `Calendar.current` device-local time).
4. **Grounding/fabrication gap — known, still open in production.** Word-overlap guards in `InsightService.swift:345-450` miss an estimated 53% of fabrications at real-device scale (per this repo's own measurement in commit `1d21c14`). The candidate semantic self-check fix (`verifyGroundingSemantic`, `InsightService.swift:1012-1036`) was tried and falsified twice — Gemma 3 1B returns "Grounded" regardless of input — and is explicitly gated out of production (`InsightService.swift:1002-1003`, "Research/validation stage only — not yet called from generateNudge or any production path"). This needs an explicit product decision on fallback conservativeness, not further silent shipping.
5. **`App/mirrorApp.swift:259-269`** — `nonisolated(unsafe) var expired` is written inside a `BGTask` expirationHandler and read from a separate `Task` with no synchronization. A real race here could cause `setTaskCompleted` to be called twice, which iOS treats as a hard error and can blocklist the task identifier.
6. **Widget entitlement can go stale.** `widget.tier` (app-group `UserDefaults`) only updates on `refresh()`/`purchase()`/`restorePurchases()` (`SubscriptionService.swift:94/104`). If a subscription lapses while the app is closed, widgets keep showing the last-written unlocked tier until the app is next foregrounded.
7. **Mood-alert cooldown is per-device**, not synced (`App/mirrorApp.swift:729,775-776`, local `UserDefaults`). Deep-tier users with two devices (e.g. iPhone + iPad) can receive duplicate mood alerts, one per device.
8. **`Core/Models/UserProfile.swift:10`** — `streakCount` field is dead: confirmed by the codebase's own comment (`Core/Utilities/GamificationEngine.swift:22`) that it's never written anywhere. It's a real, CloudKit-synced schema field that's permanently 0. Either wire it up or remove it.

## 🟡 Stability / UX rough edges

- Purchase cancellation renders as a red error banner with no special-case for `purchaseCancelledError` (`PaywallView.swift:401-406`, `SubscriptionService.swift:52-63`).
- `restorePurchases()` gives no feedback on the common "nothing to restore" outcome — a returning user can't tell if the tap did anything.
- `loadProducts()` failure leaves the paywall stuck on "Loading plans…" indefinitely, no retry affordance, no distinction between "still loading" and "network failed."
- `LLMGenerationQueue.acquire()` doesn't check `Task.isCancelled` — an abandoned request (user leaves AskView, backgrounds app) still runs to completion, wasting battery/compute.
- `backfillMissingMoodsIfNeeded` only looks back 14 days, 5 entries per pass — an entry that goes 2+ weeks without the app being opened permanently skips mood backfill for that gap.
- Date builders (`next3AM()`, `nextSunday7AM()`, month-boundary helpers) fall back to `Date()` on a DST-transition nil, firing background tasks near-immediately instead of at the intended time. Low impact, self-correcting.

## ✅ Verified clean — do not re-investigate

- No journal entry or insight text is logged anywhere; every `print`/`Logger` call in the audited files logs only counts/booleans/flags.
- No hardcoded secrets found. Keychain and `MirrorEncryption` are used correctly for real secret material. `fastlane/api_key.json` exists on disk but is gitignored and confirmed untracked.
- **A prior automated pass claimed Sentinel-theme divergence** (`@Environment(\.appDisplayMode)` declared but unused in `MoodCheckInView`, `CalendarHeatmap`, `RateUsPromptSheet`, `WhatsNewSheet`, `BrainNodeDetailSheet`). Direct inspection of all five files found this **false** — every one branches on `displayMode` correctly. No real theme divergence found in this pass.
- `ModelDownloadManager.session` (`private var session: URLSession!`) is set synchronously inside `init()` before the singleton is ever reachable elsewhere — not an actual race, just an IUO that could be a `let` for style.

## Improvement suggestions (prioritized)

1. Make an explicit, documented product decision on the grounding-gap fallback conservativeness (item 4) instead of shipping it silently.
2. Add a boundary test for the Ask cap (14→15→16 calls, month rollover, Core vs Deep) — none currently exists — and consider moving the counter off a pure local SwiftData query.
3. Clip the Ask question independently before concatenating it into the prompt, rather than as the tail of a combined-then-clipped string.
4. Replace the `MirrorModelContainer` `fatalError` with a recovery path (delete-and-recreate local store, or a "data unavailable" screen).
5. Add `Task.isCancelled` checks to `LLMGenerationQueue.acquire()`.

## New feature ideas (subsystem-specific)

- Diagnostics-settings panel (there's already a `DiagnosticsSettingsView`) surfacing repair/backfill/cleanup pass health — makes the currently-invisible self-healing machinery visible for support/debugging.
- Ask "top-up" pack for Core users who hit the monthly cap mid-cycle.
- One-time non-subscription IAP for a single Monthly Deep Report unlock, for users who don't want a recurring Deep subscription.

Ideas considered and dropped:
- Surfacing `generatedByEngine` in the UI — conflicts with CLAUDE.md, which states it is never shown in the UI.
- An on-device NLI/entailment grounding check — worth noting that similar on-device classifier approaches (Laya, Jev) were already evaluated and rejected for accuracy reasons; any new classifier idea should account for why those failed first.
