**Status 2026-10-08: Tier 1 built** (Gentle, Quiet, Curious; in-app, per device; `733bb4f`, see `3.1.0-reflection-styles.md`). Tier 2 not started. Open: native review of strings, a device check, and whether Past reflections and "How this was generated" should follow the style.

Order, from no invention risk to most:
1. **App-composed styles, no model change.** Fixed wording around the same verbatim quote (for example gentle / direct / curious), built from `groundedLocales`-style strings in all 10 languages. Grounded by construction. No rig needed for wording alone, but translations need the i18n kit.
2. **Model-written styles.** Only if a rig round matches today's numbers (FM English shown PASS about 98%; Gemma grounded quote plus one feeling sentence). Write the rubric first, N >= 10 per style per engine, then decide. Candidate surfaces: FM `@Guide` text per style, Gemma grammar per style.

Deliverables:

## 3. Write view: improvements and fixes (UI and UX), the main focus

Files: `Features/Write/WriteView*.swift` and the editor (`NoteEditorTextView` on iOS, the `NSTextView` editor on Mac). Check Classic and Sentinel themes for every change (`@Environment(\.appDisplayMode)`). Detail: `3.1.0-write-view-audit.md`.

**Status 2026-10-09:**
- **Audit + fix pass done.** Items 1–13 are fixed: list backspace, unreadable photos, Delete/Sort Done keeping formatting, inline offsets, photo paragraph styles + `PhotoMarkerRepair`, typing formatting, iOS undo history, IME composition, Mac checklist undo, Return on an empty middle item, Mac Return after checked/heading, text size, paste into lists.
- **Accessibility and translations done.**
- **Per-keystroke cost at 50k characters:** 35.7 → 11.2 ms on the iPhone 14 Pro.
- **Device run:** 117 editor tests pass on the phone.

Still open:
1. **Draft safety: DONE 2026-10-09.**
   - **The fix:** formatting-only, tag-only and date-only edits now start the same debounced draft save as typing (`WriteView.DraftChangeKey`). Before, only `text` did, so a bold-only change was lost if the app was killed before the next keystroke.
   - **Tests:** `FormattingOnlyDraftSaveTests` (bold, heading, highlight, tags/date), 37/37 with the editor and draft-store suites on the iPhone 14 Pro.
   - **Not done:** a manual kill-and-relaunch check on the phone.
   - **Still open (smaller):** the entry-wide font choice (`entryFontChoiceRaw`) isn't in the draft payload at all, so an unsaved font change is never kept. Fixing it means a `WriteDraftStore.Payload` field (old drafts decode without it).
2. **Device checks that need a person [owner]:** shake and three-finger undo, iPad hardware Cmd-Z, real Japanese/Chinese/Korean keyboards (kana → kanji, pinyin, Korean Return), VoiceOver on the checklist actions.
3. **Performance leftovers:**
   - `textViewDidChange` still reads the whole document back on every keystroke (logical text 3.5 ms + inline 3.2 ms at 50k on the phone). **Won't do now (2026-10-09):**
     - Even the 50k worst case is 11.2 ms per keystroke, inside one frame; typical entries cost 1–2 ms.
     - An incremental read-back would rewrite the inline-offset code that just had five correctness bugs fixed.
     - Revisit only if real entries get much longer.
   - ~~List Return and checklist taps decode every photo on the main thread.~~ **DONE 2026-10-09** (`PhotoAttachmentCache`):
     - **What changed:** each photo is decoded once, downsampled to its drawn size (ImageIO thumbnail) and reused across re-renders. The layout rule is unchanged.
     - **iPhone 14 Pro, 3 × 12 MP photos:** a re-render went from 47.1 to 26.5 ms. The cost over a plain redraw went from 30.6 to 11.5 ms (`PhotoRenderCostTests`).
     - **Tests:** `PhotoAttachmentCacheTests` (5).
   - ~~Photo changes rewrite all photos on the main actor.~~ **DONE 2026-10-09:**
     - **Cost before:** 20 / 52 / 83 / 134 ms on the main thread for 1/2/3/5 camera photos (iPhone 14 Pro).
     - **What changed:** the draft-attachment save now runs off the main thread. Every store operation goes through one serial queue, so a clear or load waits for a pending save, and a stale result never reaches the UI.
     - **Tests:** `WriteDraftStoreTests` (clear right after a background save leaves nothing; background save is readable when it reports).
   - `NoteEditorRenderCostTests` stops at 10k unstyled.
4. **Small items:**
   - Check the reader and Mac thumbnails for unreadable photos.
   - `insertPhotoToken` is dead code (photos always go at the end).
   - Bump `PhotoMarkerRepair.flag` to `.v2` in the first release after most devices are off 3.0.9 (owner decision).
5. **UX pass: audit DONE 2026-10-09** (`3.1.0-write-view-ux-audit.md`). Seven ranked findings:
   1. The keyboard never opens by itself (`@FocusState` with no `.focused` binding; device-observed).
   2. A back-dated new draft loses its date.
   3. A typed tag is lost without Return.
   4. `#work` becomes "##work".
   5. "Mirror suggests" fails silently.
   6. No "Now" in the date sheet.
   7. The save confirmation is hidden by the tab switch (owner call).

   **Items 1–6 fixed 2026-10-09**, plus the caret now starts at the end of the text. Item 7: the owner decided to keep Save switching to Entries.
