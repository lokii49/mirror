# 3.1.0 Write view: UX audit

Date: 2026-10-09. Roadmap §3.5. Covers capture speed, mood and tag entry, the date picker, save feedback, and error states, in the iOS Write view (`Features/Write/WriteView*.swift`, `NoteEditorTextView`).

**Method.** Read the code and traced each flow. I checked what I could on the iPhone 14 Pro (devtest app, synthetic draft, screenshots via `devicectl`; I can't tap on the device from here). **Device-observed** means a screenshot showed it. **Read-verified** means it follows directly from the cited code. Nothing was changed during the audit.

Already fixed today, not repeated here: the header layout (`aa4d221`), formatting-only draft saves (`156d0f2`), photo decoding (`8413301`), and background attachment saves (`2f32ab7`).

---

## Ranked findings

| # | Area | Finding | Evidence | Proposed fix |
|---|---|---|---|---|
| 1 | Capture speed | **The keyboard never opens by itself.** The Write tab, the widget prompt and "Edit" on an entry all pass `autoFocus: true`, and `onAppear` sets `editorFocused = true` after 0.4 s. But `editorFocused` is a `@FocusState` that no view is bound to (there is no `.focused($editorFocused)`; the editor gets a plain `Binding`), so SwiftUI drops the assignment and it stays false. Every new entry needs an extra tap before typing. The same no-op hits the other `editorFocused = true` calls (`WriteView+Actions.swift:27`, the focus-mode toggle) and `.onChange(of: editorFocused)`. | Device-observed: cold launch into Write shows no keyboard after 7 s (twice). Read-verified: `WriteView.swift:181`, `:332`, `:609`; no `.focused(` binding anywhere in `Features/Write`. | Make it plain `@State`, which the editor's binding already drives via `becomeFirstResponder`. The editor already writes `parent.isFocused` on begin/end editing, so it stays in sync. Then check the keyboard opens on Write, the widget prompt and Edit, but **not** when a sheet (mood check-in, rating) covers the screen. |
| 2 | Data | **A back-dated new entry loses its date** if you leave before saving. New-entry drafts store text, styles, mood and tags, but not the date (only edit drafts do). `onAppear` resets `entryDate = Date()` on every appear. So: pick yesterday, switch to Entries (or the app is killed), come back, and the restored draft is dated today and saves as today. | Read-verified: new-entry `WriteDraftStore.Payload` in `saveDraftToStorage` has no `entryDate`; `WriteView.swift:547` resets it on appear. | Save `entryDate` in new-entry drafts too (the payload field already exists and is optional; old drafts decode without it). Restore it in `restoreDraftFromStorage`. Same pass as the font-choice gap noted in the roadmap. |
| 3 | Tags | **A typed tag is lost unless you press Return.** Tapping elsewhere leaves the field open with its text, which isn't committed (the focus handler hides the field only when it's empty). Save ignores `tagText`. | Read-verified: `WriteView+Tags.swift`, the `tagFieldFocused` handler and `commitTag`. | On losing focus with text, commit it (same rules as Return). Saving also commits a pending tag. |
| 4 | Tags | **Typing `#work` makes a "##work" chip.** `commitTag` lowercases and turns spaces into dashes but keeps a leading `#`, and chips add their own. Also, `,`/`;`-separated input becomes one tag. | Read-verified: `commitTag`, chip `Text("#\(…)")`. | Strip leading `#`s. Split on commas, semicolons and spaces into several tags. Ignore empty and duplicate tags (already done for duplicates). |
| 5 | Mood | **"Mirror suggests" can silently do nothing.** On Free tier, without a model, or when detection returns nothing, the tap ends with no change and no message; the item is enabled on Free. | Read-verified: `detectMoodWithMirror` guards return silently; the menu disables it only for empty text or while detecting. | Hide or disable it on Free (with a Core badge or a short note). On failure, show a brief "Couldn't suggest a mood" via the existing toast/status style. Use the "…" character in "Detecting…". |
| 6 | Date picker | **No quick way back to now.** The date sheet has a graphical calendar plus a time wheel, but no "Today"/"Now" button. Future dates are blocked (good). | Read-verified: `WriteView.swift` date sheet. | Add a "Now" button in the sheet's leading toolbar; the header pill could also show a small dot when the date isn't today. |
| 7 | Save feedback | **The save confirmation is gone before you see it.** Save shows the "Saved" overlay for 1 s, then the app switches to Entries straight away (`onSave` → `selectedTab = 0`). The saved entry isn't highlighted in the list. | Read-verified: `saveDraft()` timing and `ContentView` `onSave`. | Keep the haptic. Highlight the new entry briefly in Entries (scroll to it, flash its row) instead of an overlay on a screen that's going away. Owner call: whether Save should switch tabs at all. |

## Status (2026-10-09)

Items 1–6 are fixed and pushed, checked on the iPhone 14 Pro. `WriteUXFixTests` plus the draft and editor suites pass, 34/34 on the phone.

1. **Fixed.** `editorFocused` is plain `@State`, and the keyboard opens by itself on launch (device-observed, Classic and Sentinel). `sendTextCommand` no longer requests focus, so formatting taps don't pop the keyboard. Entering focus mode now focuses the editor, as intended.
2. **Fixed.**
   - New-entry drafts store the date only when it was picked (`entryDateChosen`, set by the date pickers and the `setDate` command, cleared by "Now" and on appear), and restore it.
   - Both draft kinds store and restore the entry font (`Payload.fontChoice`; old drafts decode without it).
   - A font-only change schedules a draft save.
3. **Fixed.** Tapping away commits the typed tag; Save commits a pending tag.
4. **Fixed.** `normalizedTags`: leading `#`/`＃` dropped; `, ; ，、` split into several tags; spaces inside a tag become dashes; duplicates skipped.
5. **Fixed.**
   - "Mirror suggests" is disabled with "Core required" when it can't run (it can for everyone while `allFeaturesFree` is on).
   - No result shows "Couldn't suggest a mood" (new string, 9 languages) for 2 s.
   - "Detecting…" uses the ellipsis.
6. **Fixed.** iOS date sheet: "Now" (leading) resets to the current time, like the Mac popover.
7. **Open, owner call** (whether Save should keep switching to Entries).

Seen during the device check, not yet fixed: on opening a restored draft the caret starts at the beginning of the text, not the end.

## Checked and fine (no change)

- **Editing an entry keeps its date, tags, font and photos.** `saveAndDismiss` sets them right after `update(entry)`.
- **The next new entry starts clean after saving.** `onAppear` resets tags, date and font when the Write tab reappears.
- **Save errors are reported.** "Couldn't save this entry" alert; draft "Not saved · Retry"; the delete-with-undo snapshot for a new draft.
- **Future dates can't be picked.**

## Not covered (needs a person on the device)

- Mood/tag flows by touch, the Sentinel signal panel, VoiceOver order of the header.
- Dynamic Type at accessibility sizes for the new header.

## Suggested order

1 (keyboard), then 2 (date in drafts) and 3 + 4 (tags) together, then 5, 6, 7. Items 1–4 are small and testable. Item 7 changes navigation, so it's the owner's call first.
