## 2. Fixes (S, schema no)

- **Typing-loss bug** (pre-existing): the new-entry draft is written 0.9 s after typing stops;
  `WriteView.onDisappear` cancels that pending write without flushing, and `onAppear` restores
  the stored (older) draft over the editor. Type, switch tab within a second, come back: the last
  words are gone. Fix: flush the new-entry draft on disappear.
- "Saved to Drafts" toast label flips to "Saved" while fading: reset it after the fade.

## 3. Quick wins (S each, schema no)

- **Delete with Undo** (owner pick): no confirmation dialog for moving to Recently Deleted; an
  Undo toast for a few seconds restores it (`EntryTrash.restore`). Applies to list swipe, list
  menu, reader menu, Mac Delete key/menu. Delete Now in Recently Deleted still confirms.
- **Move to collection in the reader's … menu** (iOS and Mac reader).
- **Write's collection chip starts from the collection filtered in Entries** (new entries only,
  when the chip is untouched and the draft has none).
- **Recently Deleted easier to find:** trailing chip on the collections bar when it holds
  anything, and a row in Settings > Journal.

## 4. Owner-picked features

- **Multi-select in Entries** (M, schema no): Select in the list toolbar; tap rows to select;
  bottom bar Move to… / Delete (to Recently Deleted, with Undo). iPhone, iPad, Mac (⌘/⇧ click
  where the Mac list allows). Both themes.
- **Duplicate warning at save** (M, schema **no**, changed from the first estimate): compare the
  new text's duplicate key (`EntryDuplicates.key`, 5+ words) against the other entries' texts,
  decrypted off the main thread from a ciphertext snapshot; no stored hash, so no new field, no
  backfill and no sync churn. On a match: "You wrote this exact entry on <date>. Save anyway?"
  with Save / Keep editing. New entries only.
- **Recently Deleted retention** (S–M, schema **yes**): 7 / 30 / 90 days in Settings > Journal.
  The purge syncs (any device deleting a row deletes it everywhere), so the setting must be one
  value for all devices: a new `UserProfile.trashRetentionDays` field (default 30). Needs
  `--seedCloudKitSchema` (seed sets the field) + Deploy Schema Changes again before release.
