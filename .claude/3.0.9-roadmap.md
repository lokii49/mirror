# 3.0.9 / Mac 1.0.2 roadmap (draft, 2026-10-04)

Branch from `main` after 3.0.8 (14) / Mac 1.0.1 (14) ships. 3.0.8 already carries the iCloud data-safety work and needs its own TestFlight check (`[JournalSafety]` log, one real restore), so nothing below goes into 3.0.8.

Two tracks. Nothing is built yet.

## Track 1: Mac performance (measure first, then fix)

There is no performance baseline for the Mac app: the audits so far (`mac-parity-audit.md`) covered parity, not speed. Every fix below must ship with a before/after number from step 1.2.

### 1.1 Synthetic journal (DEBUG only)
- A launch argument seeds an **on-disk** scratch store with 500 / 2,000 / 5,000 entries, some with photos.
- Use `cloudKitDatabase: .none` (unsigned builds crash on `CKContainer`). Use synthetic text only, never real journal text.
- Not the `--macSnapshot` harness: its store is in-memory, so it hides SQLite and decryption cost.

### 1.2 Baseline measurements
`os_signpost` intervals plus `xctrace` (Time Profiler, Hangs, SwiftUI); extend `PerformanceXCTests` rather than building new infrastructure.
- cold launch to first list frame
- entry-list snapshot rebuild
- search keystroke to results
- scroll hitches in the Entries column
- cost of each app activation (⌘-Tab back into the app)
- idle CPU and energy over 10 minutes
- memory with Gemma loaded vs Foundation Models

### 1.3 Suspects, in the order to check
1. **Activation work.** `mirrorApp`'s `.active` branch runs the whole iOS foreground pipeline: insight pre-generation, reminder re-arming, one-time migrations, the review-prompt check, `JournalSafety.appDidBecomeActive`. iOS foregrounds rarely; a Mac app becomes active on every click into the window. Likely fix: throttle on Mac (e.g. once per N minutes or once per day boundary) and keep cheap checks only.
2. **Entry list renders.** `snapshotDeps` builds three O(n) hash arrays on every body evaluation. Each snapshot rebuild decrypts every entry's preview, mood and tags, and search decrypts `insightContext` for every entry on every query.
   - Likely fix: an in-memory decrypt cache keyed by entry ID plus ciphertext hash.
   - Constraint: decrypted text lives only in memory. Never written to disk, never logged (CLAUDE.md security rule 1).
3. **Full-query recomputes.** `onThisDayMatches` and `CalendarHeatmap` recompute from the full `@Query` on every render.
4. **Idle timers from 3.0.8.** Confirm the 30 s "not backed up" tick and the 10 s unreadable-entries re-check stop when nothing is pending.
5. **Gemma on Mac.** Model load time and resident memory; whether to unload after idle. Re-measure with `tools/llmrig` on Mac rather than reusing iPhone numbers (`platform-roadmap.md`).

### 1.4 Related Mac gap (data safety, not speed)
Mac rarely reaches `.background`, so `LocalJournalBackup` rarely refreshes there. Snapshot on `NSApplication.willResignActiveNotification`: the app resigns active before the user can reach System Settings to turn iCloud off. The existing modification-date check already skips the copy when nothing changed.

## Track 2: Reflection length ("just a one-liner")

### 2.1 Why it's one line today
Short is by design, because longer text invented details (CLAUDE.md, AI Model section):

| Engine / language | What's shown |
|---|---|
| Gemma (iPhone 13, 14 Pro, any device without Apple Intelligence) | verbatim quote + one feeling sentence (GBNF grammar), fixed tip on hard days |
| Foundation Models, English | verbatim quote + 1–2 guarded sentences (`FMDailyGuard`) |
| Foundation Models, de/es/fr/it/pt/ja/ko/zh | verbatim quote + a fixed translated mood line (model text not shown) |

Apple Intelligence needs an iPhone 15 Pro or newer, so the owner's iPhones run Gemma. Confirm on the device that showed it: `Insight.generatedByEngine` / the "How this was generated" sheet.

The old free-prose prompt measured ~0/40 faithful on Gemma, and ~95% of English FM free-prose outputs invented something.

### 2.2 Options, from no invention risk to most
1. **App-built lines from data the app already has** (recommended first): a second verbatim quote from today's entry, the mood trend over recent days, how often a theme recurs (`ThemeExtractionService`), the streak. Grounded by construction, works in all 10 languages, and needs no model change. Translations go through `groundedLocales` / the i18n kit like the existing fixed text.
2. **FM English: 2–3 guarded sentences** instead of 1–2, each still checked by `FMDailyGuard`. Changes the `@Guide` text, so it needs a new rig round.
3. **A second model-written sentence on Gemma.** CLAUDE.md warns against loosening the grammar. Only with rig numbers that match today's.

### 2.3 Gate
Any change to a prompt, `@Guide`, guard or grammar needs `tools/llmrig`, at least 10 samples, rubric written first. Update the "How this was generated" sheet to describe any new lines.

## Decisions (owner, 2026-10-04)
- The one-liner was seen in **English**.
- Do **option 1 and option 2**. Option 2 ships only if the new rig round matches today's numbers (shown PASS ~98%).
