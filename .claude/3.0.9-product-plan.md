# MirrorNotes 3.0.9 product and implementation plan

Date: 2026-10-07. Status: implementation started; the first archive-search slice is built and checked (see below). Remaining features are planned.
Owner direction: make 3.0.9 a substantial release; prepare for paid IAP in November 2026 as the user base approaches 1,000.
Working branch: `3.0.9-next`. Existing App Lock, Mac shortcut and check-in reminder work stays in this release.
This document supersedes the unscheduled Phase 2/3 labels for planning purposes. The older `3.0.9-roadmap.md` recorded work that shipped as 3.0.8; it was deleted on 2026-10-10 once every item was done (see git history).

## Product goal and evidence

Make MirrorNotes exceptional at three journal tasks: capture a thought, find a past moment, and reflect using the user's actual writing. Notion/Obsidian have broader editing and knowledge-management systems; we do not yet have evidence of overall superiority. Measure our advantage with task completion, retrieval accuracy, reliability and repeat use, rather than feature counts.

Baseline reviewed in code: Write has rich text, paragraph styles, nested lists, checklists, links, photos, voice notes, scanning, templates, Talk It Out and draft persistence. Entries has pins, calendar, On This Day, mood/tag/date filters and sorting. Markdown export already exists but joins entries into one document, omits tags and replaces inline photos with placeholders. Search is substring based and differs by platform. RevenueCat purchase/restore code exists; `SubscriptionService.allFeaturesFree` currently bypasses paid gates.

**Built, writing reliability (2026-10-07):**
- **Draft safety.** Drafts that can't be decrypted are never deleted by an empty flush, clear or later save; only Delete Everything removes them. Delete Everything also clears any open editor.
- **Save status.** The editor shows the real draft state (Saving…, Draft kept on this device, or Not saved · Retry; it never claims the entry or iCloud is saved), on iOS (Classic and Sentinel) and on the Mac status bar. The Mac "Draft saved" label used to show regardless.
- **Edit drafts.** Unsaved edits to an existing entry are now kept in an encrypted slot per entry UUID: text, formatting, mood, tags and date, but not photo or voice-note changes.
  - The slot fills as you type and when the editor closes, including Mac Esc, which used to drop edits silently.
  - Reopening the entry offers Restore or Discard, with a warning when the entry changed since (stable SHA-256 fingerprint).
  - Edits are never committed automatically.
  - The slot is cleared after a confirmed save and on local delete. A failed save keeps it.
- **Failed saves.** A failed new-entry save rolls back, keeps the draft and shows an alert instead of clearing.

**Built, portable archive (2026-10-07):** Settings › Your Data › **Export complete archive** writes a ZIP made with `NSFileCoordinator .forUploading` (iOS and Mac). Inside:
- `entries/`: one `.md` per entry, named with the UTC date plus UUID. The YAML front matter (quoted and escaped) holds id, created (UTC), exported_timezone, mood, tags and pinned. Formatting goes through the existing Markdown codec, inline photos become image links, and voice notes appear as a recording link plus transcript and English translation.
- `attachments/<uuid>/`: the photos, with the extension taken from the file's magic bytes, and the m4a recordings.
- `manifest.json` (format `mirrornotes-archive` v1, per-file SHA-256, exact fields for round trip) and a README.

How the export behaves:
- Entries are decrypted one at a time on the main actor and written off it.
- A field that won't decrypt makes the whole entry "unreadable". It is listed in the manifest and the summary and never written as a placeholder.
- Staging lives under tmp with complete file protection. It is removed after saving or cancelling and at launch.
- Progress and Cancel are shown. iOS saves through the document picker (by URL); Mac uses NSSavePanel plus a file copy.

**Import archive folder** (the user unzips first; iOS has no public unzip API):
- Validation runs before anything is written: format and version, a cap on count and total size, relative paths only (no `..`, absolute paths or symlinks, nothing resolving outside the folder), and checksums. Nothing is fetched from the network.
- A preview shows new, identical (skipped) and changed entries. A changed entry is never overwritten; it can only be added as a copy with a new UUID.
- The import is one save. Undo removes only imported entries still unchanged.
- Original UUIDs are kept: `JournalErasure` IDs only affect restore offers, not live entries.

Supporting changes: `Entry.archiveSnapshot()` decrypts strictly, because the ordinary accessors fall back to ciphertext or a placeholder. The style document types are now `nonisolated`; their main-actor Codable conformance trapped when decoded off the main actor.

Checked:
- 36 unit tests: round trip of every field, escaping, idempotent re-import, copy-only changes, undo, unsafe paths, symlinks, tampering and size caps, unreadable entries, duplicate timestamps. Synthetic data only.

## 1. Powerful archive search

### Experience

One search behavior across iPhone, iPad and Mac. Ordinary words search entry text and voice transcripts. Quoted text means an exact phrase. Multiple unquoted terms must all match by default. Search tags via filters or `tag:work`. Search is accent/case insensitive where appropriate; preserve original characters in displayed matches.

Filter sheet on iPhone and sidebar/popover on Mac: inclusive date range, multiple moods, multiple tags (explicit Any/All selector), collection, photos, voice notes and pinned entries. Across filter categories use AND. Within selected moods use OR. Date ranges use the device's calendar/timezone and include the full final day. Always show active filters and Clear All.

Result rows show an excerpt containing the match, highlighted words, date, mood, tags and media indicators. Opening a result scrolls to its matching paragraph; voice matches identify the recording/transcript. Provide next/previous match within the reader. No results show the active constraints and a clear way to relax them.

Initial optional syntax: `tag:`, `mood:`, `after:YYYY-MM-DD`, `before:YYYY-MM-DD`, `has:photo`, `has:audio`, `is:pinned`, quoted phrases and excluded terms. Invalid syntax gets a visible explanation, never silently changes meaning. `after`/`before` boundaries must be documented separately from inclusive picker ranges. Full Boolean query language and semantic/vector search are later work.

### Implementation

- Introduce platform-independent `EntrySearchQuery`, parser, `EntrySearchDocument` and search result models. Extract list filtering from `EntryListView` rather than adding more branches there.
- Build searchable documents from decrypted text, original transcripts, tags and mood. Label translated-transcript matches distinctly if included; never let English translation replace original-language search.
- Start with the existing memory-only decrypt cache and deterministic matching. Use relevance ordering for searches (phrase/body matches above metadata-only matches), with newest as tie-breaker; retain current sort options as overrides.
- Keep SwiftData access on its owning actor; pass immutable value snapshots to background search. Debounce input, cancel obsolete searches, and ensure older responses cannot overwrite newer ones.
- No plaintext on-disk search index. Profile before choosing a persistent index; any such design must preserve encryption and key-unavailable behavior.
- Do not silently change `SearchService.search` used by Ask: it currently falls back to recent entries when no keyword matches. Archive retrieval returns no matches honestly. Any Ask retrieval change needs a separate regression evaluation.

Acceptance: combined filters, quotes/exclusions, diacritics, CJK, empty queries, unavailable encryption keys, edits/deletes/sync and transcript updates behave consistently on both platforms. Match highlights remain accurate after Unicode normalization. Provisional target: warm search p95 <=150 ms at 2,000 entries, <=300 ms at 5,000, measured end-to-end on agreed devices; no typing or scrolling stalls. Record cold-index cost separately.

## 2. Saved views

Save a search/filter combination as a named view: for example Work this month, Difficult days, or Voice journal. Saving does not duplicate entries. Edit name/criteria, reorder and delete views. Deleting a view never deletes entries. Relative dates such as This month recalculate when opened; fixed dates remain fixed. A deleted collection referenced by a view shows a recoverable missing-filter state rather than expanding to all entries unnoticed.

Store query/name in an encrypted, versioned `SavedEntryView` payload with UUID identity. Sync through the existing CloudKit container; add defaults/optional fields compatible with SwiftData CloudKit. Expose views through the Mac sidebar and iOS Entries menu. Keep a single evaluator shared with ordinary search.

Acceptance: saved views survive restart/sync, retain Any/All semantics and sort, handle timezone/day changes, and show useful empty states. Concurrent edits require an explicitly documented conflict policy and a real two-device test; do not assume automatic sync resolves every conflict acceptably.

## 3. Reliable, comfortable writing

### Reliability first

Expose truthful draft states: Saving, Saved on this device, Save failed with retry. Local draft saving must not imply iCloud sync. Preserve explicit entry save behavior. Existing-entry edits need a recoverable encrypted edit draft keyed by entry UUID, not just new-entry draft persistence. Before adopting auto-commit for existing entries, resolve multi-device editing/conflict behavior.

Store attachments durably before claiming a draft is saved. On crash/restart reopen the recoverable draft; failed entry save keeps it. Provide Keep draft / Discard when leaving an edit. Drafts reference collection and retain intended entry date. Draft payload includes formatting and original media metadata/transcripts where available.

### Editor quality

Audit and repair rather than rewrite the native editors: multiline rich-text paste, list continuation/indent/outdent, checklist toggling, undo grouping, selection preservation, inline photos and links, hardware keyboard shortcuts, dictation, accessibility and large-text layout. Ensure formatting survives save/read/edit/export. Preserve Japanese/Korean/Chinese IME composition. Test 10k and 50k-character documents even though AI input remains capped at 10k.

Keep formatting discoverable but secondary to writing. Focus mode, line width and keyboard commands should work consistently where the platform supports them. Tables, databases, arbitrary embeds and code execution are outside this release.

Acceptance: force-quit/resume and backgrounding during edits/media save do not lose acknowledged draft content; failed writes never show Saved; changing focus or applying formatting preserves selection; IME text does not duplicate/disappear; long-entry typing meets a provisional p95 input-to-frame target <=50 ms on agreed hardware. Document the debounce recovery window accurately.

## 4. Collections: simple organization with explicit reflection scope

### Experience

Use the product term Collections. All Entries is the default aggregate. An entry belongs to zero or one collection; tags remain many-to-many descriptors. Create, rename, reorder and choose an icon/color; move entries singly or in a multi-select operation. Unfiled entries remain visible. Mac gets a sidebar; iOS gets a collection picker and collection chips. No nested folders in v1.

Deleting a collection keeps its entries and moves them to Unfiled. Show the affected count before removal. Moving entries preserves UUIDs, timestamps, pins, tags, attachments and linked references. Bulk destructive entry deletion remains a separate deliberate action.

### Data and insight boundaries

- Proposed additive model `JournalCollection`: UUID, encrypted name/settings and defaultable timestamps. Proposed nullable/defaultable collection identifier on `Entry`; avoid required relationships/unique constraints incompatible with CloudKit. Audit whether membership metadata should also be encrypted; do not expose sensitive collection names.
- Old entries default to Unfiled. Old app versions keep reading entries; they do not understand collection scope. Test old/new coexistence and record what happens when an old client writes/edits an entry.
- For 3.0.9, daily/weekly/monthly reflections continue to use all entries and the UI states that explicitly. A browsing collection never silently changes Today. Ask can gain an explicit collection filter only after its retrieval/source evaluation passes; default remains all entries.
- Per-collection automated reflections are separate work: they require scoped insight identity, caching, usage policy, notifications and compatibility design. Do not reuse global cached insights for scoped requests.

Acceptance: migration preserves all entries; moving/deleting/renaming works offline and syncs; missing/deleted collection references resolve visibly without hiding entries. Collections and saved views participate in Delete Everything, backup/restore and export/import. Test incomplete sync arrival order and concurrent collection deletion/entry movement.

## 5. Complete export and safe import

### Portable package

Export all entries, a collection, selected entries or filtered results to a ZIP containing one `.md` file per entry, an attachments directory and a versioned manifest. Use stable date-plus-UUID filenames, UTC timestamps with timezone context, escaped YAML metadata for mood/tags/collection and stable relative media paths. Export formatting with the existing codec/service; include audio, transcripts and inline photo placement. Unsupported styling must be documented, not silently represented as lossless.

Retain current text/PDF exports. Provide progress, cancel, destination selection and an export summary. If encrypted content is unavailable, report affected entries and offer retry; never package placeholders as a complete backup. Stream media where possible; avoid decrypting the entire archive into one memory buffer. Plaintext exists only in the user-requested output and short-lived export staging, which must be cleaned after completion/cancel and on a later launch following a crash.

Obsidian support means a usable Markdown folder that can be opened/imported as a vault. Notion support in this wave means a Markdown/ZIP import workflow verified in current Notion, with documented fidelity limits. No Notion API integration, account credentials or automatic cloud uploads. Export is distinct from the encrypted recovery backup.

### Import

Preview entry/media counts, dates, collections and warnings before writing. First support our versioned package and the existing plain-text/Markdown inputs. Add an Obsidian Markdown folder importer with a narrow documented subset of frontmatter/daily-note date parsing. Unknown metadata stays available in import diagnostics/source files; do not invent mood or date. Notion exports can follow only after fixture-based compatibility is established.

Stable manifest UUIDs make our package imports idempotent. On an existing UUID with changed content offer Skip / Import as copy; no silent overwrite. External files use explicit duplicate review. Stage and validate before committing; cancellation/failure must have an explicit recovery path without partially applied invisible imports. Reject unsafe archive paths, cap expanded size/count, and never fetch remote attachments. Show results and offer undo of the import batch until subsequent edits make removal ambiguous.

Acceptance: export/import round-trip text, supported formatting, dates, moods, tags, collection membership, photos/audio/transcripts with synthetic fixtures; duplicate filenames and Unicode are safe; interrupted/low-storage exports/imports preserve the journal; UUID collision, path traversal and archive-size limits are tested. Verify the package manually in Obsidian and Notion before making compatibility claims.

## 6. Entry links and backlinks (stretch)

Let users insert a link to another journal entry via search/date picker. Display a readable date/title preview, resolve by entry UUID, and show Linked from in the reader. This is distinct from the editor's existing web links. Deleted targets show Entry unavailable and never navigate to a different record. Keep link storage semantic, not dependent on the current preview text; preserve links through formatting edits and exports.

Use a versioned encrypted inline-reference representation with a derived memory-only reverse index. Determine the old-client rendering behavior before choosing a codec extension. Export internal links as relative Markdown paths and resolve them on our package import. Optional `[[` insertion shortcut follows the picker once IME and paste behaviors pass.

Acceptance: link rename/preview changes, target deletion, sync order, partial export, cyclic links and round-trip imports all work. Backlinks are actual authored references, never inferred relationships presented as fact.

## 7. Related moments and source-backed reflection (stretch)

In the reader offer up to three Related moments based initially on explicit shared tags/links and deterministic term matching. State the reason: Shared tag: work, or Linked from this entry. Exclude the current entry, respect selected scope, and offer hide/dismiss. Do not infer relationships between people or diagnose patterns. No embeddings or new AI prompt in the initial implementation.

For Ask/digest/report, audit existing source metadata first. Any new source references must resolve to the exact input entries; model-written quotations must match the source. A cited entry supports the answer's evidence, not a claim that the answer is guaranteed true. Users can open sources and see a quote in context. Deleted sources become unavailable honestly.

Any retrieval/context/prompt change needs a written rubric and llmrig round (N >=10 at minimum; include representative cases per engine/language). Include no-match, contradictory days, plans versus events, changed names and hospital refusals. Preserve the known grounded daily output path. Ship only if quality meets the baseline; otherwise keep deterministic related moments and existing reflection behavior.

## 8. Templates and custom AI styles

Custom writing templates (stretch): user-authored title/body with supported formatting, insert/replace preview, encrypted storage, edit/delete, export/import. Applying a template must not overwrite an existing draft without a deliberate replace action. Template text becomes entry text only when the user inserts it; AI must not treat unanswered prompts as life events. Test empty/unanswered templates in the grounding rig when they affect generated insights.

AI personas: treat as reflection styles, not fictional identities with medical/professional authority. Proposed initial presets Gentle and Direct only; keep fact/quote rules unchanged. Arbitrary user system prompts are out of scope. First determine whether approved deterministic wording can satisfy demand; model-written variants require separate FM/Gemma/localized measurements. Current grammar and non-English fixed lines limit meaningful style variation. Do not advertise styles the engines cannot deliver. Default remains today's behavior; saved preference is encrypted and synced. Ship later if measured usefulness is weak or grounding regresses.

Existing Core/Deep reflection entitlements are the baseline; exact new-feature allocation and pricing must be checked against live products before release copy is finalized.

Verify offerings/products, purchases, restore, trial eligibility, cancellation, expiry, upgrade/downgrade, offline entitlement behavior and cross-platform access in StoreKit/sandbox/TestFlight. Ensure cancelled/failed purchases do not lock data. Never infer entitlement failure from a transient network error.

Prepare clear early-access transition copy: what changes, when it changes, what stays available, and how to restore. Owner decision needed before activation: immediate paid transition, grace period or an existing-user benefit. The stale CLAUDE instruction about no grandfathering is not assumed to settle this new launch decision. Do not expose journal text to analytics. Any behavioral telemetry needs a separately defined consent/privacy design; use aggregate store metrics and opt-in feedback meanwhile.

## Verification and definition of done

- Focused unit tests for query semantics/Unicode, archive parser/round-trip, migrations and conflict handling; do not test UI implementation trivia.
- Existing editor/AI regression suites and both platform builds after relevant changes. No model downloads/rig runs concurrently with performance baselines.
- UI flows in Classic/Sentinel, VoiceOver, Dynamic Type, keyboard-only Mac, and iPad split view; real devices for biometrics, widgets, notifications, CloudKit and purchase lifecycle.
- Production model additions are additive/defaultable; deploy new record types/fields before release. Export a recovery backup before real-data upgrade checks; test on synthetic data first. Never reset a user's store to resolve migration trouble.
- New records appear in schema, backups/restores, Delete Everything and diagnostics counts. No silent plaintext caches or sensitive logs. App Lock must cover every new window/sheet and clear/withhold search results while locked.
- Performance report at 500/2,000/5,000 entries with device/build identifiers, cold/warm latency, memory, cancellation and scrolling. Threshold misses trigger profiling and a documented release decision, not unsupported performance claims.
- Compare identical tasks with Notion/Obsidian: capture a voice-backed entry; recover interrupted writing; find a passage using date+tag+mood; export and reopen a journal; inspect reflection sources. Record completion, time and failures in an opt-in usability study. Only then claim a tested advantage.
