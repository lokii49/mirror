`generateFollowUp` and `generateGuidedQuestion` (`InsightService.swift:1188`, `:1207`) call `localGenerate` with the default `gemmaPlan: .samePrompt`. On Gemma that is free prose with `FOLLOW_UP_SYSTEM` / `GUIDED_ENTRY_SYSTEM`. 3.0.5 fixed exactly this failure class on the other four surfaces. Both of your phones (iPhone 14 Pro and iPhone 13) are Gemma-only.

**Both are reachable on Gemma:**
- **Follow-up chip** (`WriteView+Actions.swift:334`). It is gated only on:

  - `LocalLLMService.isModelAvailable`, which is FM **or** Gemma;

  - `!LLMGenerationQueue.isBusy`.
- **Talk It Out.** Question 1 comes from `WritingPrompts`; questions 2 and later come from `generateGuidedQuestion`. Its own comment (`TalkItOutView.swift:310`) says neither path has been run against a real model.
- **Validator.** `validateFollowUp` checks shape only: ends in "?", 8–160 chars. It has no content or grounding check.

The risk is a question that invents something, e.g. "How did the rain make you feel?" when the entry has no rain. It is lower-stakes than a false reflection, and the 3.0.5 notes don't claim these two surfaces are fixed. It is still the same failure class.

- **Step 0 (done).** Rig cases live in `GroundingSampleHarness.followUpRigCases` / `guidedRigCases`, dumped by `test_dumpFollowUpPromptsForRig`.

  - (b) Return `.unsuitable` on Gemma and hide the chip and generated Talk It Out questions on Gemma devices. Talk It Out would fall back to `WritingPrompts` for every question.
  - Avoid a "no capitals" name filter. It breaks German, where nouns are capitalized, and does nothing for ja/ko/zh.
- **fr/ru register.** Gemma follow-ups currently say vous/вы 7/10 and 10/10. The **composed-template** design in (a) and option (b) both settle it. A free-form French or Russian question under GBNF can't cleanly exclude "vous"/"вы".

### 1b. When a daily reflection appears, and a skipped day [re-checked]

> **DONE 2026-09-28** (`2d2f091`, `0e19bbb`): option 2 + the label from option 1, owner-approved, relaxing CLAUDE.md rule 4 for this one case.
> - **Second reflection.** It is made the same day when today's reflection covered only earlier days and the user writes today, at most 2 per day. A failed extra attempt isn't saved.
> - **Next morning.** The card keeps last night's reflection only while it's about yesterday's or today's writing and nothing new was written. The widget follows the same rule.
> - **Label.** "From what you wrote on <day>" appears in both themes and 10 locales.
> - **Past list.** One row per (day made, day it's about).
> - **Not verified by eye or on a device yet.**
> - **Reflection time minutes DONE** (`7b56edd`): the gate compared the hour only, so 8:30 opened at 8:00. It now compares hour and minute (`mirrorApp.isAtOrPastReflectionTime`).
> - **Mood race DONE** (`fd4d306` + catch-up fix). `MoodAutoDetector` is now the one path for automatic mood detection.
>   - **One detection per entry:** a request for an entry already being detected joins it, and a mood the user picks meanwhile wins.
>   - **Save waits for it:** the save paths await detection before the reflection and the mood-alert check.
>   - **Reflections fill missing moods first:** `runDailyNudgeIfNeeded` fills moods for the entries it reads.
>   - **Save and leave works:** the background catch-up now also makes the same-day second reflection when the user leaves the app right after saving.
>   - **Still open (older than this work):** a voice note that finishes transcribing after save starts neither mood detection nor a reflection; the next trigger picks both up.


User report 2026-09-28: a reflection appeared at 18:02 on a day with no entry yet. That is by design. `runDailyNudgeIfNeeded` (`mirrorApp.swift:375`) makes **one real reflection per calendar day**, and only when:
- there are at least 3 readable entries;
- something was written after the last real reflection;
- it's past the reflection hour (the nightly pass skips this check).

**Gemma's reflection quotes only the newest day's entries.** On Apple Intelligence phones the free-prose prompt sees the last 3 entries.

**What follows:**
- **Writing after today's reflection gets nothing today.** Saving calls `runDailyNudgeIfNeeded`, which stops at the "today already has a real reflection" guard. Try Again stops at the same guard; `userInitiatedRetry` is checked after it.
- **It shows up tomorrow** on the "Today" card.
- **Evening writers' "Today" card is always yesterday's writing.**
- **A day can be skipped (Gemma).** If the user writes again the next day before that day's reflection is made, only the newest day is quotable. Pinned by `DailyNudgeSourceDayTests`.

**Options:**
1. **Label the card with the day it reflects,** e.g. "From your 27 Sep entry". Cheap, no rule change; doesn't fix the skip.
2. **Allow one more reflection today** when today's reflection had no same-day entry (none between the start of today and its `generatedAt`) and the user has since written today.
   - Removes both the lag and the skip; evening writers then get their reflection right after writing.
   - Up to 2 rows per day: check the widget, notification and Past reflections.
   - **Relaxes CLAUDE.md security rule 4** ("never regenerate within 24h"), which needs the owner's explicit OK.
3. **Build Gemma's source from everything written since the last reflection**, not only the newest day. Fixes the skip without changing how often reflections appear. Rig-test first: earlier rig work saw Gemma blend days when older entries were in the prompt.

### 2. Saved insights from 3.0.4 are never replaced [re-checked]

Nothing in 3.0.5 regenerates a current-period insight just because it came from the pre-grammar Gemma path. `isGrammarGrounded` is only used to *skip* the repair and cleanup passes (`CachedInsightRepair.swift:32`, `UngroundedInsightCleanup.swift:90/110`).

- **Monthly report.** The September window is Sep 24–30. On 3.0.4, Gemma users are generating September reports now with the prompt that fabricates. Most will be the "Couldn't confirm" fallback card, and some will be partial fabrications that slipped past the word-overlap guards.
  - `runMonthlyReportIfNeeded` (`mirrorApp.swift:656`) regenerates only when both hold: 24h have passed since the report, and a newer entry exists (`weeklyDigestIsStale`).
  - It also only runs in the last week of the *current* month.
  - So a September report built by 3.0.4 is permanent once Sep 30 passes. 3.0.5 may go live around Sep 28–29 (auto-release), but that doesn't rescue most reports: auto-update is slow, and even an updated device only regenerates after a new entry plus 24h, all before Sep 30.
- **Weekly digest.** The digest for Sep 21–27 was plausibly generated today (Sunday) on 3.0.4 for most users (not observed). If so, it is permanent for the same reason: the ISO week ends today.
- **Conflicts with a shipped promise.** The 3.0.5 notes say "Reflections created before this update aren't changed." A regrade must be announced in the 3.0.6 notes, e.g. "your most recent monthly report and digest are rewritten from your own sentences."
- **Proposal:** a one-time pass, `mirror.didRegradePreGrammarInsights.v1`, following the `UngroundedInsightCleanup` pattern: flag-gated, non-destructive, and it rewrites in place rather than deleting, so CloudKit doesn't produce tombstones.
  - Scope: the **most recent** monthly report and digest, where `generatedByEngine == .gemma` (or nil) and `!isGrammarGrounded(content)`.
  - Action: regenerate each once, even though it is outside the normal window (September's report during Oct 1–7).
  - **Decided 2026-09-27: latest period only.** Older reports and digests stay as they are.

### 3. `MirrorModelContainer` crashes permanently on init failure [re-checked]

`MirrorModelContainer.swift:18` calls `fatalError` if `ModelContainer` init throws, so a corrupt store or a full disk means a crash on every launch.

- **Safe default:** show a "Your journal couldn't be opened" screen with a retry button and a support link. **Never auto-delete the store**, because unsynced entries would be lost.
- **Risky, verify before using:** retrying the same store with `cloudKitDatabase: .none`. Opening a CloudKit-backed store without CloudKit drops persistent-history tracking. Core Data can then put the store into read-only mode, and entries written that way may never sync. Don't ship this without a device test that proves sync still works after the retry.
- **Bigger than it looks.** `shared` is a static initializer, and two call sites assume it can't fail: `mirrorApp.swift:18` and `AddJournalEntryIntent.swift:24` (Siri). Turning it into a throwing or optional result changes both. The intent needs an error dialog, not a crash.
- It needs a way to test it, e.g. inject a failing configuration. It's done only when a test exercises it.

### 4. `BGProcessingTask` expiration race [re-checked]

`mirrorApp.swift:259` writes `nonisolated(unsafe) var expired` from the expiration handler and reads it from a separate `Task` with no lock. If the work finishes at the same moment it expires, `setTaskCompleted` can be called twice.

- Fix: an `OSAllocatedUnfairLock<Bool>` "completed once" guard around both calls.
- Only the `nightlyInsights` handler has this problem. The three `.appRefresh` tasks use SwiftUI `.backgroundTask` and never call `setTaskCompleted` by hand.

## P1: should ship

5. **The Ask question has no length cap** [re-checked].
   - Foundation Models: `buildAskMessage` (`InsightService.swift:1979`) puts the question *last* and then clips the whole message to 5,700 chars, so a long question can be cut off silently.
   - Gemma: `groundedAskPlan` (`:2819`) appends the question with no clip at all, so a very long question pushes the prompt past its budget.
   - `AskView`'s `TextField` has no limit.
   - Fix: cap the question in the view and in `ask()` (~500 chars), and clip entries instead of the question.
6. **`LLMGenerationQueue` ignores cancellation** [re-checked]. `run` calls `acquire()` and then `operation()` with no cancellation check (`LLMGenerationQueue.swift:21`). An Ask or follow-up that is cancelled while waiting in the queue still runs the model once it gets its turn. Fix: add `try Task.checkCancellation()` after `acquire()`, inside the `defer`-release scope. It's a one-liner, and it needs a test that the queue is still released.
7. **Measure Gemma's `EMOTION_DETECT` accuracy.** It has never been measured. The Laya/Jev eval measured *those* models against the task, not Gemma. Since 3.0.5, mood picks the grounded digest options, sets the energy adjective's bucket, and keeps Sad/Numb out of "let go of" in the monthly report. It also still drives Mood Alerts. A wrong mood now produces confidently wrong text. Use llmrig with 12 labels and N≥10 hand-labelled entries across en plus 2–3 other locales. Fix only if the numbers are bad.
8. **3.0.6 release notes** in all 10 locales. None exist yet. Include:
   - "Keep writing" questions on iPhones without Apple Intelligence now quote your own words.
   - A reflection now appears after you write that day.
   - One about an earlier day says which day.
   - "How this was generated" shows exactly what was read.
   - Reflections now wait until the exact minute you set.
   - Daily reflections on iPhones without Apple Intelligence: one plain sentence about how you seem, plus a short fixed suggestion only on hard days (no more generic "take a few deep breaths").
9. **Word count is wrong for Japanese and Chinese** [re-checked]. `strippedWordCount` (`NoteEditorTypes.swift:148`) splits on whitespace, so a ja/zh line counts as about one word. Korean uses spaces and is fine. It feeds:
    - `Entry.wordCount`;
    - the follow-up chip's 20-word gate, which a CJK draft never reaches;
    - XP (`GamificationEngine.swift:34`);
    - `InsightService.swift:2100` entry scoring, which uses a short-entry threshold;
    - the editor word badge and daily goal;
    - Settings total words;
    - the "most words" sort;
    - monthly report totals.
   Fix it with `enumerateSubstrings(options: .byWords)`, which segments CJK. Stored `wordCount` values need a one-time recount.
10. **Native-speaker review for ru and ja** through the review kit (`tools/i18n/review`, `build_md.py` → `~/Downloads/mirror-translation-review.md`, `apply_review.py`). This depends on finding a person; it doesn't block the release.
11. **"How this was generated" sheet** — DONE (`a04bf8f`, `de9909e`). For grammar-path insights it shows only what Gemma was sent: the nudge's same-day entries, and "none sent" for earlier context in digests and monthly reports. It no longer decrypts the whole history on every render.
