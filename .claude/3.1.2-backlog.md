## A. Live bugs

### A1. Widgets sell features that are already free [verified, LIVE]
- `Core/Services/SubscriptionService.swift:97-109` writes `widget.tier` only inside `updateTier`, which runs only after a RevenueCat call succeeds. The `.deep` default from `allFeaturesFree` is never written to the app group.
- `Widget/WidgetTheme.swift:55` defaults a missing key to `"free"`.
- Failure: first launch offline or RevenueCat errors → Nudge/Prompt/Entries/Digest/Monthly widgets show the lock view with "Core · $2.99/mo" (`DailyNudgeWidget.swift:190`) and link to `mirror://upgrade` → `PaywallView` (`App/ContentView.swift:384`), which has no `allFeaturesFree` check and sells Core/Deep.
- Fix direction: write `widget.tier` in `init` when `allFeaturesFree`; guard the paywall route.

### A2. Editing a voice-only entry can corrupt it on every device [verified, LIVE]
- The decrypt guard `textDecryptionFailed` (`Core/Models/Entry.swift:57`) only checks `encryptedText`. A voice-only entry has `text == ""`, stored unencrypted, so the guard never fires. EntryDetailView guards (:251, :310, :505) have the same gap.
- `MirrorEncryption.decryptOptionalData` (`Core/Utilities/MirrorEncryption.swift:83`) returns the ciphertext as if it were plaintext on failure; string fields come back as the "[Encrypted entry unavailable on this device]" placeholder.
- `WriteView.swift:557-574` loads these values; `WriteView+Actions.swift:94-108` writes every voice field back unconditionally.
- Failure: device B without A's key (iCloud Keychain off or not yet synced) opens a voice-only entry from A and changes the date or a tag → A's ciphertext is re-encrypted under B's key, the placeholder is saved as tags/transcripts, mood and transcript are dropped; CloudKit syncs it back to A.
- Fix direction: a guard covering every encrypted field (data and strings); refuse to edit when any fails.

### A3. Encryption fails open when the key can't be read [verified, LIVE but rare]
- `MirrorEncryption.swift:37-40` (`encryptString`) and `:85-90` (`encryptDataArray`) return plaintext when `key()` throws → plaintext syncs to CloudKit.
- `:73-76` (`encryptOptionalData`) returns nil → the photo, voice note or style data is silently dropped on save.
- Trigger needs a Keychain read failure with no cached key (items default to WhenUnlocked). Low frequency, high consequence.

### A4. Weekly digest and monthly report background refreshes are never armed [verified, LIVE]
- `App/mirrorApp.swift:1138` and `:1157`: `scheduleWeeklyDigestFallback()` / `scheduleMonthlyReportFallback()` are called only from inside their own handlers, so the first request is never submitted. The daily nudge fallback is fine (armed at `:363`).
- Failure: a user who doesn't charge overnight (the nightly `BGProcessingTask` needs power) and doesn't open the app on Sunday gets no digest. The "Sunday 7AM" refresh in CLAUDE.md never happens.
- Fix direction: submit both on `.background` next to `scheduleDailyNudgeFallback()`.

### A5. A fallback daily reflection is regenerated and re-inserted on every trigger [verified, LIVE]
- `mirrorApp.swift:718`: the "new entry since last nudge" gate only counts real nudges, so today's entry always passes once the newest row is a fallback.
- `mirrorApp.swift:793-794` inserts a new CloudKit-synced row each time. Only the same-day extra reflection records a failed attempt (`extraReflectionFailedAttemptKey`).
- Failure: every foreground, entry save, BG refresh and nightly pass after reflection time either runs a full 3-attempt FM generation or inserts another copy of the deterministic unsupported-language / `.unsuitable` card. Unbounded rows. Breaks Security Rule 4 (no regeneration within 24h). The fallback copy promises a retry "after you add more", which isn't what happens.

### A6. Fallback detection breaks across languages [verified, LIVE]
- `Core/Services/InsightService.swift:1199` (`isUngroundedFallback`) compares by exact equality against the current locale's `String(localized:)`; `legacyUngroundedFallbacks` is English only.
- Failure: a fallback saved on a German iPhone syncs to an English Mac, or the user changes language → treated as a real reflection: shown `.loaded`, counted as first nudge seen, blocks today's generation (`newestToday-is-real`), pushed to the widget by `syncNudgeToWidget` (`mirrorApp.swift:1281`) — the 2026-09-20 widget bug again.
- Fix direction: match against every locale's string (or a stored marker); a schema field would need the CloudKit deploy gate.

### A7. Stale regeneration can replace a good digest/report with the fallback [plausible, LIVE]
- `mirrorApp.swift:932-934, 995-997`; `Features/Insights/InsightViewModel.swift:318, 422`.
- The extra daily reflection and `PreGrammarInsightRegrade` refuse to let a fallback replace a real row; these paths don't. Newest wins.

### A8. Monthly report regenerates every 24h with no new writing [plausible, LIVE]
- `InsightViewModel.swift:388-389` serves the cache only under 24h and never checks staleness (the background runner does).
- Failure: in the last week of the month, opening Monthly daily regenerates from the same entries with new text; combined with A7 it can turn into the fallback.

### A9. Retired free-prose prompt still reachable [plausible, HIGH if confirmed]
- `InsightService.swift:2833` (`groundedNudgePlan`) falls back to the device locale and returns `.samePrompt` for non-English; `:742` vs `:3840` per the agent's trace. When entry language detection returns nil (texts under 20 chars, or confidence < 0.35) and the device locale is outside the 10 supported languages (e.g. nl), the unsupported-language check is skipped and execution reaches the `DAILY_NUDGE_LEGACY_SYSTEM` free-prose loop.
- Expected: the honest card. This is the same failure class as the invented-scene incident. Confirm with a unit test before fixing.

### A10. Delete Everything leaves journal-derived text on widgets [verified, LIVE]
