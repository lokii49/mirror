# 3.1.9: Retention messages (App Store Connect)

Asked 2026-11-13 ("make this part of 3.1.9"). Apple's retention messages: a short card Apple shows
when a subscriber starts to cancel in the system subscription screen. App Store Connect only, no
app code, no binary change. Apple help: https://developer.apple.com/help/app-store-connect/manage-subscriptions/configure-retention-messages

## Decisions

- **Two messages, text only.** Core message on `mirror_core_monthly` + `mirror_core_yearly`, Deep
  message on both Deep products (one live message per subscription; a canceller loses different
  things per tier).
- **No retention offer yet.** Paid plans start 15 Nov 2026, so no one meets a "paid for N months"
  eligibility rule; ASC converts offer prices by exchange rate, which ignores the five PPP bands
  (CLAUDE.md, Subscription Tiers), so every territory would need overrides. Revisit with churn data.
- **No image yet** (3840×2160 or 5244×2950 if added later).
- **Not the Retention Messaging API** (separate pre-release program for real-time server
  messages); nothing here needs it.

## Copy rules

- Header ≤ 66 characters, body ≤ 144 (ASC API docs, `RetentionMessageLocalization`). The script
  checks both.
- No price, discount, "free month", offer or trial wording in header or body: every canceller sees
  the same text and App Review rejects it. No superlatives, guilt or unverifiable claims.
- **Free tier promise**: never imply entries or history go away. A canceller keeps writing,
  reading, search, iCloud backup and every reflection, digest and report already made (cards and
  widgets). Only *new* insights stop. Widgets are left out of the "stop" list because saved
  reflections stay readable in them.
- Feature names follow the app's own strings in `mirror/Localizable.xcstrings` (Ask = Fragen /
  Preguntar / Demander / Chiedi / 質問 / 질문 / Perguntar / вопросы / 提问). Same tone as the
  app: du (de), tu (es/pt-BR/it), vous (fr), вы (ru).

## Copy (English)

| | Header | Body |
|---|---|---|
| Core | Your journal stays yours, whatever you choose | Without Core, you keep writing, search, iCloud backup and every reflection already made. New daily reflections, Ask and weekly digests stop. |
| Deep | Your journal stays yours, whatever you choose | Without Deep, you keep writing, search, iCloud backup and everything already made. New reflections, Ask, digests, reports and mood alerts stop. |

All locales: `tools/asc/retention_messages.json` (en-GB, en-US, de-DE, es-ES, es-MX, fr-FR, it, ja,
ko, pt-BR, ru, zh-Hans). Store listing locales today: en-GB (primary), es-ES, it, ja, ko, ru; the
subscriptions themselves only have en-US. The app's 10 languages are covered anyway; Apple falls
back exact locale → language → default.

## How to apply

`tools/asc/retention_messages.rb` (API key `fastlane/api_key.json`, Ruby `jwt` gem):

- `ruby tools/asc/retention_messages.rb` — dry run, prints every request.
- `--apply` — creates the two messages, a version each, the localizations, and links the four
  subscriptions. Idempotent: reuses messages by reference name, patches changed text, skips what
  matches. Only edits a version in `PREPARE_FOR_SUBMISSION`.
- `--status` — messages, version states, locales, which message each subscription uses.

It never submits. Review submission is separate (ASC: Retention Messaging › message › Add for
Review, or a `reviewSubmissionItems` with `retentionMessageVersion`), and needs the owner's OK
like any submission. Retention messages are reviewed on their own, not with a binary, so they
can go before, with or after the 3.1.9 build.
