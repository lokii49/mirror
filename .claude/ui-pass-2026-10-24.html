Interface text that follows the user's text size

Today, reading text grows with the user's setting and everything around it doesn't. A reflection at the largest size sits between a 9-point label and 10-point buttons. The entry row title stays at 13 points. Someone who needs large text gets it for the paragraph and loses it for the controls.

  • 622 .font(.system(size:)) calls and 249 MirrorTheme.mono(size) calls (Sentinel) use fixed sizes. Only 18 use text styles like .body.
  • 17 readingFont calls, plus the reader and Write editors, already scale. That's backlog A19, so the pattern exists.
  • 37 lineLimit(1) and 18 minimumScaleFactor shrink text to fit. At large sizes that means clipped or tiny words, worse in German and French.

How

A small set of named roles beside readingFont, each tied to a system text style, so the default size looks the same as today and the user's setting moves it:

.mirrorFont(.label)        // 11 pt today, scales with .caption2
.mirrorFont(.meta)         // 12 pt, .caption
.mirrorFont(.rowTitle)     // 15 pt, .subheadline
.mirrorFont(.cardTitle)    // 17 pt, .headline
.mirrorFont(.button)       // 15 pt semibold, .callout
MirrorTheme.mono(11, relativeTo: .caption2)   // Sentinel

At accessibility sizes, rows of buttons and chips stack vertically (ViewThatFits), as in the third phone. One file per commit, biggest first: InsightView (48), MonthlyReportView (34), MoodTimelineView (32), EntryListView (32), OnboardingFlow (31), WriteView+Subviews (30). Each one is checked in Classic and Sentinel at the default size and at AX3. Widgets are left for a later pass.

Charts VoiceOver can describe

Mood Timeline, the calendar heatmap and Brain View have 8 accessibility labels between them, and none uses accessibilityChartDescriptor. A VoiceOver user hears that a chart exists, not what it says.

  • Mood Timeline: a chart descriptor (dates × mood valence), which gives Audio Graphs for free: VoiceOver plays the line as a rising and falling tone. Plus a one-sentence summary built from the same numbers the chart draws.
  • Heatmap: each week is one element ("Week of 13 October, 5 entries, mostly Calm") instead of 7 unnamed squares.
  • Brain View: the top themes as an ordered list ("Work, 14 entries, linked to Sleep and Family"). Tapping a theme already opens its entries.

The summaries are counts and mood names the app already has. No model writes them.

Every icon button says what it does

There are 121 lines with a bare SF Symbol and 126 accessibility labels in the whole app. Many of those symbols sit inside a Label or next to text and are fine. The rest read as "button" or as the symbol's file name ("sparkles", "arrow.left.arrow.right").

Method: list every Button whose only content is an Image, run the Accessibility Inspector over Write, Entries, Insights and Settings in both themes, and give each a label in the nine languages. Decorative symbols get .accessibilityHidden(true).

Mac: hover, right-click, drag, and windows that remember

  • Drag an entry onto a collection. Drag a row from the list onto a sidebar collection to move it there, using the store's existing JournalOrganizationStore.move. Multi-select drags move them all. Undo uses the existing toast.
  • Hover. There are 5 onHover uses in the app, one of them on the entry row. Add hover states to toolbar buttons, Insights cards, Brain nodes (name and count tooltip) and the related-entries list in the reader.
  • Right-click. Entry rows have a menu. Insights cards, Brain nodes and related entries don't. The commands already exist in the menu bar, so the menus reuse them.
  • Windows remember. With @SceneStorage per window, the selected entry, sidebar state and list scroll position come back after relaunch, for the main window and each entry window.
  • Drop into Write (photo or text from Finder or Safari). Useful, but WriteView is at the Debug main-thread stack limit, so this has to be a separate view with no new body modifiers, launch-tested on the 14 Pro. Decision 6.

iOS: Controls, a zoom into entries, and glass

  • Controls. Two ControlWidgets, New Entry and Log Mood, that people can place in Control Center, on the Lock Screen bottom corners, or on the Action button. They open Write or the existing mood check-in sheet and add nothing to storage. They sit in the existing widget extension beside the 7 widgets.
  • Zoom transition. Opening an entry from the list zooms from its row (matchedTransitionSource + .navigationTransition(.zoom)), and swiping down returns to the same row. With Reduce Motion on it stays a plain push. Classic and Sentinel both.
  • Glass on the selection bar. EntrySelectionBar and the other custom bottom bars use the iOS 26 glass the keyboard bar and voice recorder already use, so they match the system tab bar. iOS 17 and 18 keep today's material.

Rules every step keeps

  • Every themed iOS view ships in Classic and Sentinel and is checked in both.
  • Nothing touches WriteView's body; Write changes go in split views and get a launch test on the 14 Pro.
  • No CloudKit schema change, nothing model-written, no new stored fields.
  • The two header rows in Write stay as they are (your call, 16 October).
  • Commits stay local; nothing is pushed until you say so.
Your decisions

Seven choices

Pick an answer for each, then copy the summary and paste it into the terminal. Recommended answers are preselected.

1. How large should interface text go?

Full range means up to the largest accessibility size, with stacking layouts. Capped stops at the largest standard size (xxxLarge), which is less layout work but leaves people who use accessibility sizes behind.

2. Chart summaries and icon labels

No visual change. VoiceOver only.

3. Monthly Report section icons

Today they're system orange, blue, green and a gold that fails contrast.

4. Controls for Control Center, Lock Screen and Action button

A new surface. It's standalone, with no storage, and needs iOS 18.

5. Mac inspector column for entry details

The reader pane from 21 October already shows the reflection and related entries. An inspector would move mood, tags, collection and word count into a column you toggle with ⌥⌘I.

6. Drop a photo or text into Write on Mac

Riskiest item because of the WriteView stack limit.

7. Which branch?

3.1.6 has Builds 27–29 on TestFlight, not submitted, with the Ask fix waiting for the iPhone 13 check.
