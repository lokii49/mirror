## The device (from Xcode 27.1's simulator profile, `iPhone19,4`)
| | Points (@3x) | Size class | Notes |
|---|---|---|---|
| Outer display (closed) | 466 × 678 | compact width | Wider and shorter than any iPhone; hinge-side corners 8 pt, others 59 pt; Dynamic Island |
| Inner display (open) | 669 × 951 | **regular width** | The biggest iPhone display. Still `userInterfaceIdiom == .phone`. |
- Touch ID, not Face ID. App Lock already reads `context.biometryType` (`AppLock.swift:61`); the audit checks the copy shows "Touch ID".
- Resizable scenes: Split View 50/50 and video PiP resize the app at any time.
- **Side controls:** on the outer display (and the inner one in landscape and when partly folded), tab bars, toolbars, the back button and the status bar move to a vertical strip on the side. Only the inner display in portrait keeps horizontal bars. Wide items (text buttons, segmented controls) stay in the nav bar or collapse into an overflow menu.
- **Fold:** when partly folded, system components (sheets, alerts, menus, toolbar buttons) avoid the crease by themselves. Custom interactive elements must stay out of it. Scrolling content may cross it.
- **Poses:** closed, open, book (partly folded), tent/propped, laptop, standing. Apple: design for the two size classes, not per pose, and keep the same features in every pose.

## What Apple says to fix ([prepare page](https://developer.apple.com/iphone-duo/prepare/))
1. Don't size from `UIScreen.main`. Use view/window bounds or `GeometryReader`/`onGeometryChange`, and re-read on every change.
2. Don't make layout decisions from orientation.
3. Don't branch on `userInterfaceIdiom`, don't treat regular width as iPad, and don't check specific sizes.
4. Test with the resizable simulator, iPhone Mirroring resizing, and the **iPhone Duo simulator** (best).
5. Run Apple's resizability skill: `xcrun agent skills export`. It doesn't catch everything.

### The structural problem: the layout swap
`ContentView` shows `phoneLayout` (`TabView`) when compact and `ipadLayout` (`NavigationSplitView`) when regular. Opening or closing the Duo flips the size class, so the whole view tree is replaced.
- The section is mapped across (`onChange(of: sizeClass)`), but everything under it is rebuilt: open sheets, the entry being read, scroll position, keyboard focus, and typing since the last debounced draft save.
- On iPad this only happened on a Split View resize. On the Duo it happens every time the user opens the phone, often mid-entry.

**Proposed fix:** one `TabView` for both size classes with `.tabViewStyle(.sidebarAdaptable)` (iOS 18+; the app targets 17.6, so iOS 17 keeps today's code behind `#available`). Apple names this pattern for the Duo ("a modifier can move a tab bar to a sidebar"). The tabs stay the same views, so state survives the fold. Settings, a sidebar item on iPad today, becomes a tab section visible only in the sidebar, or stays where the iPhone has it (the Insights toolbar). That's a design call, below.

## Plan
### Phase 1: audit (about a day, no code changes)
- Run the app on the iPhone Duo simulator in:
  - closed, portrait and landscape;
  - open, portrait and landscape;
  - partly folded;
  - Split View half;
  - PiP-resized.
- Repeat in both themes, with the synthetic `--perfSeed` journal and seeded insights.
- Screens:
  - Write (empty, long entry, formatting panel, photo, voice note, mood/date/tag sheets, Talk It Out);
  - Entries (list, calendar, filters, search, reader);
  - Insights (Today card, digest, report, mood timeline, Ask, Brain View);
  - Settings (every screen, including App Lock);
  - onboarding, What's New, paywall, rate prompt, mood check-in;
  - widgets on the outer and inner displays;
  - the notification content extension.
- **Fold test:** type in Write, then open/close the device. Check text, selection, keyboard and open sheets survive. Read an entry, fold, and check the reader stays open.
- Run `xcrun agent skills export` and go through its findings.
- **Output:** `.claude/3.1.3-iphone-duo-audit.md`, with screenshots and a must-fix / should-fix / nice list.

### Phase 2: must-fix (code)
- Replace the two `userInterfaceIdiom` branches with a space-based rule. For example, popover when the editor is at least ~600 pt wide and not compact; otherwise the `inputView` panel. To be confirmed in the audit.
- Move custom controls out of the side strip and the fold. Prefer system toolbars and `safeAreaInset` over overlays. Keep full-bleed backgrounds with inset controls.
- Fix any `GeometryReader` that caches a size.
- App Lock: confirm the copy shows "Touch ID" on the Duo (it already follows `biometryType`).

### Phase 3: Duo design (the major part; owner approves mockups first)
- **Navigation:** the `sidebarAdaptable` `TabView` above. Tab bar when closed, sidebar when open, no tree swap.
- **Open (regular width):**
  - Entries: list plus reader side by side (two-column split inside the tab).
  - Insights: Today card and digest beside each other, or the card list beside the selected detail.
  - Write: a readable column width with the formatting panel as a popover.
- **Closed (466 pt wide, short):**
  - content inset from the side strip;
  - check that the Write toolbar and mood/date chips fit the shorter height;
  - sheets use the system's side controls.
- **Partly folded:**
  - nothing interactive in the crease;
  - Write as a "laptop" (text above the fold, keyboard below) comes from the system keyboard;
  - Talk It Out's question above and the answer field below is worth a look but optional (Apple: no pose-only features).
- **Sentinel:** the same structure in its visual language; the corner brackets must not land under the side strip.
- **Mockups:** Classic + Sentinel, closed / open / partly folded, for Write, Entries and Insights. Owner picks before building.

### Phase 4: test and release
- Re-run the Phase 1 matrix after fixes. Run the existing device suites on the iPhone 14 Pro to catch regressions on a normal iPhone, and check the iPad layout (it moves to the same `TabView`).
- Screenshots: optional now. If time allows, capture Duo screenshots in the simulator for the store and the featuring nomination (Helpful Details: "optimized for iPhone Duo, all poses").
- Update the 3.1.2 release notes (already drafted, `c63ae83`) with a Duo line in 10 languages.
- Submit by about Oct 20 with automatic release.
