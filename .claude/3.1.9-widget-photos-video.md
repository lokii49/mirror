# 3.1.9: Still Open widget, photo sizes, drag and drop, video

Asked 2026-11-13. Design canvas: https://claude.ai/artifact/SNVB5sda9i92c8oz457hd6 (owner picked
every recommended option, 2026-11-13). Built in this order, one commit series each, local commits only.

## Owner decisions (2026-11-13)

- **Widget tier:** the open-items list is Core (widgets are Core); the Checklist / Numbered /
  Reminder buttons work on Free, because they're writing.
- **Ticking on the widget:** yes. Queued in the app group (entry id, line index, SHA-256 of the
  line's words; never the words), shown ticked at once, applied on the next app-active only if
  the line is still the same checklist item.
- **Photo size:** Small / Medium / Full Width in the photo's long-press menu (iPhone, iPad; Mac:
  thumbnail menu). Stored as `InlineStyleRange.photoSize` on the photo's one inline character;
  the `[[mirror-photo-N]]` token never changes.
- **Video sources:** Photos picker, drag and drop, Journaling Suggestions. At most 4 videos per
  entry, 720p, first 60 s. Needs the owner's CloudKit schema deploy before any TestFlight build.

## 1. Still Open widget — done

  count) and the tick queue, both in the app group, both in `WidgetBridge.journalDerivedKeys`.
- `StillOpenWidgetSync` (app): rebuilt on every widget refresh when the journal revision changed;

  opens the entry), `mirror://scratch-note?start=checklist|numbered|reminder`.
- Checked: unit tests (StillOpenWidgetTests 6), widget layouts rendered (small/medium/large,
  locked, empty), throwaway XCUITest on the iPhone 18 Pro simulator for all four links and the
  entry open. **Device (14 Pro, MN Dev build of f262686, 2026-11-13, owner's hands): all five steps

## 2. Photo size — done (bdf7830 + review fixes)

- `PhotoSize` (36% / 64% / full of the line), `PhotoSizes` helpers (`PhotoSize.swift`). iOS editor:
  Photo Size section in the photo menu and in UIKit's link menu on linked photos (Suggestion maps);
  resized from `PhotoAttachment.fullBounds`; tiles keep tile size. Reader: `FractionWidthLayout`
  (share of the reading column). Mac: thumbnail menu; trailing-photo ranges carried by photo order
  across body edits and photo removal; such entries stay editable on Mac 1.1.9.
- **Older versions:** 3.1.8 / Mac 1.1.8 show the photo full width and drop the size if they edit
  the entry; Mac 1.1.8 treats an entry with a sized (or linked) trailing photo as read-only (its
  round-trip check can't reproduce the range), as it already did for Suggestion maps.
- Checked: PhotoSizeTests (9) + codec/editor/photo/suggestion suites on the simulator; throwaway
  XCUITest from a wiped draft: plain photo (our menu) and linked photo (UIKit link menu + Photo
  Size) both set Small, the link still opens Maps, reader shows it small. Canvas deltas: 36/64
  rather than 33/62, "Full Width". **Pending:** 14 Pro hand check; Mac run (built only).
## 3. Drag and drop — done (f7ca74c + 584f3eb)

- Pictures dropped (Photos, Files, Safari) or pasted (Paste, Cmd-V) go through Write's photo path
  after the drop point's paragraph (`insertDroppedPhotos` → the Suggestion insert). Paste offered
  for images (`MirrorEditorTextView.acceptsPastedImages`); duplicate hand-overs inserted once.
- Moving a photo: the list-item gesture (hold ~0.2 s, move): `handlePhotoDrag` + shared
  `beginRowDrag/updateRowDrag/endRowDrag`. The system drag of photos is off in Write; drops the
  editor takes use `dropPerformer = .delegate` (UITextView inserted dragged attachments itself,
  as duplicates, on the 14 Pro).
- Mac: pictures dropped anywhere on the text attach like a pasted photo (`onDropImages`).
- Checked: Cmd-V on the simulator; owner on the 14 Pro: move without duplicate, menu still on
  hold, checklist drag fine, Paste fine. **Not checked:** dropping from another app on iPhone/iPad,
  Mac drop.
