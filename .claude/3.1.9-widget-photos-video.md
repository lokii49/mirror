# 3.1.9: Still Open widget, photo sizes, drag and drop, video

Asked 2026-11-13. Design canvas: https://claude.ai/artifact/SNVB5sda9i92c8oz457hd6 (owner picked
every recommended option, 2026-11-13). Built in this order, one commit series each, local commits only.

## Owner decisions (2026-11-13)

- **Widget tier:** the open-items list is Core (widgets are Core); the Checklist / Numbered /
  Reminder buttons work on Free, because they're writing.
- **Ticking on the widget:** yes. Queued in the app group (entry id, line index, SHA-256 of the
  line's words; never the words), shown ticked at once, applied on the next app-active only if
  the line is still the same checklist item.
- **Photo size:** Small / Medium / Full Width in the photo's long-press menu (iPhone, iPad; Mac:
  thumbnail menu). Stored as `InlineStyleRange.photoSize` on the photo's one inline character;
  the `[[mirror-photo-N]]` token never changes.
- **Video sources:** Photos picker, drag and drop, Journaling Suggestions. At most 4 videos per
  entry, 720p, first 60 s. Needs the owner's CloudKit schema deploy before any TestFlight build.

## 3. Drag and drop — done (f7ca74c … e208137)

- Pictures dropped from other apps (Photos, Files, Safari) or pasted (Paste, Cmd-V) go through
  Write's photo path after the drop point's paragraph (`insertDroppedPhotos` → the Suggestion
  insert). The editor performs those drops itself (`dropPerformer = .delegate`); in-app picture
  drops are refused (UITextView inserted the dragged attachment itself: a duplicate). Paste is
  offered for images (`MirrorEditorTextView.acceptsPastedImages`); repeated hand-overs go in once.
- Moving a photo (e132ef6, after the owner found the hold "totally off"): hold 0.45 s → the photo
  lifts (haptic); slide >10 pt → it moves (slot follows the finger, page auto-scrolls, first/last
  allowed); let go without sliding → the editor's photo menu (UIEditMenuInteraction: Photo Size
  first, Open Link on linked photos, Copy, Save to Photos, Share). UIKit's context/text-item menus
  don't open on photos; a shorter touch scrolls/taps. Shared row-drag code with checklists.
- Mac: pictures dropped anywhere on the text attach like a pasted photo (`onDropImages`), also
  when Finder/Safari add a path or URL string.
- Checked on the simulator by XCUITest (scratch copy /private/tmp/mirror-chk, HoldDragUITests and
  friends, not committed): still hold → menu, Photo Size → Small; drift 6/9 pt → menu, 30 pt →
  nothing; rest 0.3 s then scroll → scrolls; hold and slide → below the last line; 16-line entry
  auto-scrolls; linked photo → Open Link; quick swipe → nothing; checklist drag; Cmd-V once. Owner on the 14 Pro: the
  first versions (duplicate, no move, whole-editor lift) — all fixed since; latest build installed.
  **Not checked:** a drop from another app on a device, Mac drop and Mac Size picker (built only).
  Full unit suite on the simulator at 9c4dadc: 1243 pass, 1 LLM wall-clock perf test failed under
  load; it passes alone (e132ef6 run, with 132 editor/photo/widget tests).
- Widget gallery order (owner): Still Open first, monthly report last.
