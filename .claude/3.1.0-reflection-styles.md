# Reflection styles: design note (draft, 2026-10-08)

Status (2026-10-09): Tier 1 (Gentle, Quiet, Curious) is built and in 3.1.0. Tier 2 was measured in rig round 12 (model-written Plain and Question, FM English) and FAILED; nothing model-written is built. See the end of this note.

Rule from the roadmap: model-written styles ship only with rig evidence. App-composed styles (fixed wording around a verified quote) need no rig for the wording itself.

## What a reflection is today

| Engine / language | Shown |
|---|---|
| Gemma, English | `You wrote, "<verbatim sentence>"` + one feeling sentence (GBNF grammar) + fixed tip on hard days (`groundedNudgeTips`) + app-picked second quote at display time |
| FM, English | verbatim quote + 1-2 sentence insight checked by `FMDailyGuard`; fixed tip on hard days |
| FM de/es/fr/it/pt/ja/ko/zh | verified quote + fixed translated mood line (`groundedLocales.feel`) |
| Gemma other 9 languages + ru | Gemma only picks the quote; the app composes fixed translated text (`groundedLocales`) |
| Any other language | honest card, no model |

A style must work on every row, or say plainly where it doesn't apply.

## Tier 1: app-composed styles (no new model output)

The quote stays exactly as verified today. A style only changes the fixed text around it. Because the text is fixed, it is grounded by construction and can be translated once through the i18n kit (`mirror/tools/i18n/grounded_locales.py`, then `groundedLocales`).

Proposed set (names are placeholders):

| Style | After the quote | Source of wording |
|---|---|---|
| Gentle (default, today) | feeling line + tip on hard days | unchanged |
| Quiet | nothing: the quote only (plus the second quote at display time) | none; cheapest, no translation |
| Curious | one question built around the quote, `What's underneath "..."?` | existing `followUpQuestion` templates in `groundedLocales` |
| Practical | feeling line + the fixed tip on every day, not only hard ones | `groundedNudgeTips` (needs neutral/good-day tips written and translated) |

Not proposed: anything that sounds like therapy, praise or prediction. The settled rules stand: no extra app-built lines such as mood trend, theme or streak.

Open design points:
- Where the style is stored: `UserDefaults`/`AppStorage` per device, not a SwiftData model, so there is no CloudKit schema change (owner preference: standalone, no schema unless asked). Consequence: it does not sync across devices.
- Where the picker lives: a row in Settings (Reflection) plus a preview line using synthetic text.
- Stored `Insight.content` must stay in the format old clients parse (`You wrote, "..." ...`). Same trap as the second quote: a style that changes the stored shape would leak to 3.0.9 and Mac 1.0.2 parsers, the widget and the lock screen. Safest: store the Gentle form always and apply the style at display time, like `reflectionWithAlsoQuote`. The widget and notifications would then show Gentle regardless of the style; decide whether that is acceptable.
- "How this was generated" must describe the style.

## Tier 2: model-written styles (rig first)

Only if Tier 1 leaves a real gap. Candidates: FM `@Guide` text per style (warmer, plainer, shorter), a Gemma instruction variant. Gate, from CLAUDE.md and the roadmap:
1. Write the rubric first (`tools/llmrig/fm/RUBRIC_FM.md` style: invented names/scenery, "never before", feelings not in the entry, quote fidelity).
2. N >= 10 per style per engine on synthetic cases, including the hospital-day and ordinary-day cases.
3. Compare with today's numbers: FM English shown PASS about 98% (fallback 3.6%); Gemma grounded 0 lenient on the feeling-line-only form.
4. Any style below today's numbers does not ship. A longer FM insight already failed round 10 and is out.
5. Outside English on FM the model insight is not shown at all (`FMDailyGuard` is English word lists), so model-written styles would be English-only on FM. Gemma styles are English-only too, since other locales are fixed text.

## Order of work

1. Owner picks the Tier 1 set and the storage/display rules (questions below).
2. Build Tier 1: a `ReflectionStyle` enum, display-time composition next to `reflectionWithAlsoQuote`, Settings row, tests for each style x engine x language row (quote preserved verbatim, old-client format untouched).
3. Translate the new fixed strings through the i18n kit (10 locales), mark for native review.
4. Decide on Tier 2 after seeing whether Tier 1 is enough.

## Questions for the owner

1. Is the Tier 1 set (Gentle, Quiet, Curious, Practical) right, or do you want different names or fewer?
2. Display-time only (widget and lock screen always show Gentle) or should the style also apply to the widget and notifications?
3. Per-device setting (no schema) is the default here. OK?
4. Is a Tier 2 (model-written) style something you want to measure at all, or skip until Tier 1 ships?

## Tier 2 result (rig round 12, 2026-10-09)

The owner chose two model-written styles to measure: Plain (one short sentence, no reading of what it means) and
Question (one open question about the entry). 990 runs, gates fixed before the run (`tools/llmrig/fm/RUBRIC_FM.md`,
round 12). Both failed on fallbacks: Plain 10.3% overall, three cases at 10/10; Question two cases above 30%.
What they did show added little: Plain was mostly the mood label restated ("You felt drained."), and Question was
mostly "What does it mean...", which Tier 1's app-built Curious already gives with no model and no fallback.
Decision: no model-written style. Tier 1 stays as built. Reopen only with a new idea that Tier 1 cannot do, and a
new round.
