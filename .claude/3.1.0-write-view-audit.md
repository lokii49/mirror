# Write view audit (3.1.0)

Date: 2026-10-08. Source: a read-only code audit by a subagent of `Features/Write/` (iOS `NoteEditorTextView.swift`, Mac `NoteEditorTextViewMac.swift`, codec, `WriteView*.swift`). Nothing below was run on a device. "Read-verified" means I opened the cited code and the claim follows from it; "agent-reported" means I have not re-read it yet and it must be checked before a fix. Line numbers are as of commit `733bb4f` and drift.

Method: fix in small commits, one regression test per fix (the headless harness in `FormattingCombinationTests.swift` / `ListBackspaceTests.swift` can drive `shouldChangeTextIn`; paragraph-style toolbar conversion needs a first responder, so verify that on device).

## Fixed

| # | Defect | Status |
|---|---|---|
| 1 | iOS: Backspace right after a list marker ate one marker character; the half-marker was saved as text and a second marker was added on re-render (Mac already handled it via `leaveListAtParagraphStart`). | **Fixed.** `leavesListFromMarker` turns the item into a body paragraph. `ListBackspaceTests` fails without the fix, passes with it (bullet, dash, checklist, numbered). Device check still needed. |
| 5 | `removeInlinePhoto`: `(token.index + 1)..<count` traps when the token index is past the photo array (a photo that failed to decode or save). | **Trap fixed** (read-verified: the top of the function already guards `attachCount < tokens.count` and `token.index < photos.count`; the renumber loop is now `stride`). **Still open:** a photo that fails to decode renders as nothing, so token order and attachment order can diverge and the wrong photo can be deleted or reassigned. No unit test for the fix (coordinator-private path). |
| 3 | Checklist "Delete Done" was one tap with no confirmation or undo, and it and "Sort Done" set `inlineStyleData = nil` on iOS and Mac (`replaceDocument`), wiping bold/links/highlights for the whole entry. | **Fixed** (read-verified). `NoteEditorCodec.remapInlineStyles` cuts ranges at row edges (UTF-16) and moves them with their rows; formatting on deleted rows goes with them. iOS sort/delete and Mac `replaceDocument` use it. Delete Done now asks first ("Delete checked items?") from all three entry points via `WriteView.applyTextCommand`, closing the Aa panel/popover before the alert. Tests: 5 codec tests in `NoteEditorCodecTests`, 2 coordinator tests in `ListBackspaceTests` (`ChecklistBulkOpsKeepInlineTests`), 2 new Mac self-test checks (45/45 PASS). **Still to do:** the two alert strings are not in `Localizable.xcstrings` yet (CLI builds don't extract; English in every language until a localization pass); device check that the alert appears from the iPhone Aa panel, the iPad popover and the Mac popover menu; still no undo (item 7, and item 6 on Mac). |
| 4 | iOS: inline formatting shifted by one or more characters after list Return, typing into a marker, `1.`+space, a list/heading command, photo deletion, and photo/scan/Talk It Out appends. | **Fixed** (read-verified). Tests: `InlineOffsetsAfterListEditsTests` (Return, marker typing, `1. `, list command, trailing trim) and 3 `adjustInlineStyles` codec tests. **Not covered:** photo removal has no coordinator test (needs a rendered photo); removing a photo line still leaves its paragraph-style slot (item 2). |

**Performance (not measured at 50k)**

- Per keystroke: `logicalText`, style encode and inline extract in `textViewDidChange`; `strippedWordCount` in `WriteViewModel.text.didSet` (full `.byWords` segmentation for Japanese and Chinese); `logicalText` and `displayTextEquivalent` again in `updateUIView`.
- `logicalText` sorts photo tokens with `String.distance` comparators (O(n) per comparison); tokens already arrive in order.
- List Return and checklist taps re-render everything, decoding every photo with `UIImage(data:)` on the main thread.
- The editor measures the full document each pass (`isScrollEnabled = false`).
- `NoteEditorRenderCostTests` stops at 10k characters on unstyled text.
- Formatting-only edits never schedule a draft save (`WriteView.swift` watches `text` only); photo changes rewrite all photos on the main actor.

**Polish and accessibility**

- Keyboard-dismiss button has no accessibility label; toolbar icons use fixed point sizes.
- iOS checklist toggle is tap-only (no VoiceOver action); Mac checkboxes have `accessibilityDescription: nil`.
- `insertPhotoToken` is dead code (`.photo(index:)` is never sent), so photos always go at the end.
- `print("[scrollDiag]…")` in `NoteEditorTextView.swift` is intentional (logs caret geometry only, no text); the audit called it stray. Leave it.
