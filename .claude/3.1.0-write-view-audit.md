# Write view audit (3.1.0)

Date: 2026-10-08. Source: a read-only code audit by a subagent of `Features/Write/` (iOS `NoteEditorTextView.swift`, Mac `NoteEditorTextViewMac.swift`, codec, `WriteView*.swift`). Nothing below was run on a device. "Read-verified" means I opened the cited code and the claim follows from it; "agent-reported" means I have not re-read it yet and it must be checked before a fix. Line numbers are as of commit `733bb4f` and drift.

Method: fix in small commits, one regression test per fix (the headless harness in `FormattingCombinationTests.swift` / `ListBackspaceTests.swift` can drive `shouldChangeTextIn`; paragraph-style toolbar conversion needs a first responder, so verify that on device).

| 4 | iOS: inline formatting shifted by one or more characters after list Return, typing into a marker, `1.`+space, a list/heading command, photo deletion, and photo/scan/Talk It Out appends. | **Fixed** (read-verified). | 2 | iOS: entries with a mid-text photo shifted or lost paragraph styles and baked list markers into the text; the reader and Markdown export put inline formatting on the wrong characters after a photo. | **Fixed** (read-verified, three causes). (a) The renderer gave a photo line two paragraph-style slots (the segment before the token and the one after each counted their own piece) while the encoder and the Mac codec store one; a segment's first index is now the number of line breaks before it. (b) `logicalText` swapped tokens in before reading paragraphs, so attribute lookups after a photo used inflated offsets; it now reads paragraphs in display offsets (`displayedMarkerLength`) and substitutes tokens per paragraph. (c) Inline ranges count a photo as one character but `EntryDetailView` and `MarkdownExportService` applied them at `entry.text` offsets; both now map through `NoteEditorCodec.inlineRangesInTextCoordinates`. With one slot per photo line, the empty pieces on both sides of the token share it, so a list slot on the photo line (list item, Return, attach a photo) drew a marker before and after the photo and the one after was saved (`[[mirror-photo-0]]•  `); the piece after a token now continues the line (`continuesLine`: no marker, no number step). Tests: `PhotoParagraphStyleTests` (heading below a photo, list below a photo, two photos — all fail before 4247f0f; photo on a bulleted/checklist/numbered slot at start and after text — fails on 4247f0f; cleanup result stays clean through render + keystroke), codec mapper test, export test. Full target 678 passed, 0 failed; Mac self-test 45/45. Entries already saved with shifted styles are not repaired (the original styles are gone); the list markers that were saved into text are removed once per device by `PhotoMarkerRepair` (on app active, after the first backgrounding, like `CJKWordCountRecount`): a marker right after a photo token that starts its line, and a list item's own marker at the start of its text on lines below the first photo (`NoteEditorCodec.repairPhotoMarkerDamage`, inline ranges moved with the deletions; entries whose inline data can't be decrypted are skipped). | 7 | iOS: undo history was lost after almost any edit, and the Undo button stayed enabled while doing nothing. | **Fixed** (probe-verified cause). Tests: `EditorUndoTests` (list Return undo/redo, bold undo, typing before a command still undoable, typing grouping and Return, loading not undoable, append undoable, `MirrorEditorTextView.undoManager` routes to the history). **Performance (not measured at 50k)**

- Per keystroke: `logicalText`, style encode and inline extract in `textViewDidChange`; `strippedWordCount` in `WriteViewModel.text.didSet` (full `.byWords` segmentation for Japanese and Chinese); `logicalText` and `displayTextEquivalent` again in `updateUIView`.
- `logicalText` sorts photo tokens with `String.distance` comparators (O(n) per comparison); tokens already arrive in order.
- List Return and checklist taps re-render everything, decoding every photo with `UIImage(data:)` on the main thread.
- The editor measures the full document each pass (`isScrollEnabled = false`).
- `NoteEditorRenderCostTests` stops at 10k characters on unstyled text.
- Formatting-only edits never schedule a draft save (`WriteView.swift` watches `text` only); photo changes rewrite all photos on the main actor.

**Polish and accessibility**

- Keyboard-dismiss button has no accessibility label; toolbar icons use fixed point sizes.
- iOS checklist toggle is tap-only (no VoiceOver action); Mac checkboxes have `accessibilityDescription: nil`.
- `insertPhotoToken` is dead code (`.photo(index:)` is never sent), so photos always go at the end.
- `print("[scrollDiag]…")` in `NoteEditorTextView.swift` is intentional (logs caret geometry only, no text); the audit called it stray. Leave it.
