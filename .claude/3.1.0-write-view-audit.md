# Write view audit (3.1.0)

Date: 2026-10-08. Source: a read-only code audit by a subagent of `Features/Write/` (iOS `NoteEditorTextView.swift`, Mac `NoteEditorTextViewMac.swift`, codec, `WriteView*.swift`). Nothing below was run on a device. "Read-verified" means I opened the cited code and the claim follows from it; "agent-reported" means I have not re-read it yet and it must be checked before a fix. Line numbers are as of commit `733bb4f` and drift.

Method: fix in small commits, one regression test per fix (the headless harness in `FormattingCombinationTests.swift` / `ListBackspaceTests.swift` can drive `shouldChangeTextIn`; paragraph-style toolbar conversion needs a first responder, so verify that on device).

**Performance (measured; `KeystrokeCostTests`, iPhone 14 Pro, styled entry with 3 photos, per keystroke)**

- 10k chars: 4.9 ms (didChange 2.4, updatePass 1.3, wordCount 1.2).
- 50k chars: 35.7 ms (didChange 23.8, updatePass 6.0, wordCount 5.7): about two dropped frames per keystroke, before UIKit's own layout.

Fixed, 9a7702a. **iPhone 14 Pro: 50k 35.7 → 11.2 ms (didChange 8.4, updatePass 0.2, wordCount 2.5), 10k 4.9 → 2.5 ms**, so a keystroke at 50k now fits in one frame (before UIKit's own layout). Simulator: 50k 67.1 → 24.1 ms, 10k 11.0 → 6.5 ms.
- Inline extraction was quadratic: `displayToLogical` / `logicalToDisplay` and `applyInlineStyles`' boundary lookup scanned every paragraph per attribute run (30 ms at 50k). Binary search now (`paragraphIndex(atOrBefore:)`, `firstParagraph(startingAt:)`): 6.4 ms, linear.
- `updateUIView` rebuilt the logical text and the display equivalent on every pass to detect outside changes; skipped when the text is what the editor last showed (`isShowing`): 12.5 → 0.5 ms.
- `WriteViewModel` re-counted every word per keystroke; `ParagraphWordCounter` re-counts only changed paragraphs for space-separated text (11.4 → 5.0 ms). Japanese/Chinese text is still counted whole: word segmentation differs per paragraph (test caught 9 vs 11), and the shown count must match the stored one.
Left: `textViewDidChange` still reads the whole document back (logical text 7 ms, inline 6 ms, style encode) on every keystroke; on the phone that is logical text 3.5 ms + inline 3.2 ms at 50k; not worth an incremental rewrite now.


- Per keystroke: `logicalText`, style encode and inline extract in `textViewDidChange`; `strippedWordCount` in `WriteViewModel.text.didSet` (full `.byWords` segmentation for Japanese and Chinese); `logicalText` and `displayTextEquivalent` again in `updateUIView`.
- `logicalText` sorts photo tokens with `String.distance` comparators (O(n) per comparison); tokens already arrive in order. (Not measured to matter with 3 photos.)
- List Return and checklist taps re-render everything, decoding every photo with `UIImage(data:)` on the main thread.
- The editor measures the full document each pass (`isScrollEnabled = false`).
- `NoteEditorRenderCostTests` stops at 10k characters on unstyled text.
- Formatting-only edits never schedule a draft save (`WriteView.swift` watches `text` only); photo changes rewrite all photos on the main actor.
